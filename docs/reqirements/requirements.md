## 1. 목표와 범위

작업공간별 캠페인과 설문을 만들고, QR·URL로 로그인 없이 응답을 받아 질문별 결과와 링크별 제출 수를 분석하는 서비스다.

**MVP 핵심 흐름:** 회원 로그인 → 작업공간·캠페인 생성 → 설문·질문 작성 및 발행 → 링크/QR 배포 → 비회원 응답 → 대시보드 분석.

**MVP 이후:** 방문 대비 설문 완료율, 고급 QR 디자인·관리, 고도화된 AI 요약.

## 2. 기능 요구사항과 비즈니스 규칙

### 2.1 회원·작업공간·캠페인

| ID | 기능 요구사항 | 비즈니스 규칙 / 검증 기준 | 상태 |
|---|---|---|---|
| FR-01 | 회원 가입·로그인 및 회원정보 관리 | 이메일은 회원 간 유일하며 비밀번호는 안전한 해시로 저장한다. | 제안 |
| FR-02 | 회원별 작업공간 생성·수정 | 회원은 여러 작업공간에 소속될 수 있다. | 확정 |
| FR-03 | 멤버십 관리 | 동일 회원·작업공간 조합은 중복될 수 없다. 권한 없는 회원은 해당 공간을 수정할 수 없다. | ERD 반영 / 제안 |
| FR-04 | 캠페인 생성·수정·조회 | 캠페인은 하나의 작업공간에 소속되고 여러 설문을 가질 수 있다. | ERD 반영 |
| FR-05 | 소셜 로그인 | Google·Kakao 지원 여부와 계정 연결 규칙을 정한다. | 미결정 |

### 2.2 설문·질문·선택지

| ID | 기능 요구사항 | 비즈니스 규칙 / 검증 기준 | 상태 |
|---|---|---|---|
| FR-06 | 설문 생성·수정·임시저장·발행 | 초안(DRAFT)은 응답 불가. 발행(PUBLISHED) 후 기간 조건에 따라 응답 가능. | 확정 / 제안 |
| FR-07 | 설문 기간 설정 | `start_at`, `end_at`은 각각 NULL 가능. 둘 다 NULL이면 무기한. 둘 다 값이 있으면 시작 < 종료. | 확정 |
| FR-08 | 설문 종료 | 종료(CLOSED) 상태에서는 신규 제출 불가. 기존 응답은 보존. | 제안 |
| FR-09 | 질문 추가·수정·정렬 | 단답·장문·단일선택·복수선택 유형, 필수 여부, 표시 순서를 관리한다. | 확정 |
| FR-10 | 선택지 추가·관리 | 발행 후 **기존 선택지 수정·삭제 금지**. 발행 후 신규 추가 가능 여부는 별도 결정. | 확정 / 미결정 |
| FR-11 | 발행 후 질문 수정 | 수정은 허용하되 질문 유형 변경·삭제·필수 여부 변경처럼 기존 통계를 왜곡할 수 있는 변경은 제한 범위를 정한다. | 확정 / 미결정 |

**응답 가능 조건(제안):** `status = PUBLISHED`이고 `(start_at IS NULL OR now >= start_at)`이며 `(end_at IS NULL OR now < end_at)`이고 접근 링크가 활성 상태여야 한다.

### 2.3 링크·QR·응답

| ID | 기능 요구사항 | 비즈니스 규칙 / 검증 기준 | 상태 |
|---|---|---|---|
| FR-12 | 설문별 여러 URL 발급 | URL은 유일하고 링크 이름·유입 채널을 구분한다. | 확정 |
| FR-13 | QR로 설문 접근 | URL을 QR로 제공한다. 별도 고급 QR 편집기는 MVP에서 제외한다. | 확정 / MVP 이후 |
| FR-14 | 로그인 없는 응답 | 비회원도 공개 설문을 조회하고 제출할 수 있다. | 확정 |
| FR-15 | 답변 저장 | 하나의 응답은 여러 답변을 갖는다. `(response_id, question_id)` 조합은 유일하도록 설계한다. 선택지는 해당 질문 소속이어야 한다. | ERD 반영 / 제안 |
| FR-16 | 응답 임시저장·제출 | `created_at`과 `submitted_at`을 분리한다. 제출 시 필수 질문과 답변 형식을 검증한다. | 확정 |
| FR-17 | 중복 참여 제한 | 동일 설문 중복 제출을 제한한다. 쿠키/토큰만으로 완전한 차단은 불가능하며 식별 범위와 보관 기간은 결정해야 한다. | 확정 / 미결정 |
| FR-18 | 제출 요청 중복 처리 | 연속 클릭·재시도에도 동일 응답이 두 번 제출되지 않도록 상태 변경을 원자적으로 처리한다. | 제안 |
| FR-19 | 링크별 응답 출처 기록 | 응답에 사용한 `survey_link_id`를 저장하고 해당 링크의 설문과 응답의 설문이 일치해야 한다. | 확정 |

**제출 트랜잭션(제안):** 질문/선택지 유효성 검사 → 답변 저장 → 응답 상태 `SUBMITTED` 및 제출 시각 기록을 일관되게 처리한다.

### 2.4 분석·대시보드

| ID | 기능 요구사항 | 비즈니스 규칙 / 검증 기준 | 상태 |
|---|---|---|---|
| FR-20 | 설문별 제출 수 조회 | 기본 통계는 제출 완료된 응답만 포함한다. | 확정 / 제안 |
| FR-21 | 질문별 통계·선호도 | 선택지별 선택 수와 비율, 질문별 유효 답변 수를 보여준다. | 확정 |
| FR-22 | 주관식 결과 조회 | 단답·장문 응답을 목록으로 조회한다. | 확정 |
| FR-23 | 링크/채널별 성과 | 링크별 제출 응답 수를 집계하고 비교한다. | 확정 |
| FR-24 | 요약 정보 저장 | ERD의 `요약` 엔티티를 사용할 경우 생성 시점·갱신 기준을 정한다. 자동 요약 구현 범위는 별도 결정한다. | 미결정 |
| FR-25 | 방문 대비 완료율 | 방문 수집과 유효 방문 정의가 필요하므로 MVP 이후로 연기한다. | MVP 이후 |

**비율 계산(제안):** 단일 선택형은 선택지 선택 응답 수 / 해당 질문의 유효 답변 수. 복수 선택형은 선택지별 선택 응답자 수 / 해당 질문의 유효 답변 수로 계산하며, 합계가 100%를 넘을 수 있다.

### 2.5 경품·당첨 — MVP 포함 범위 미결정

ERD에는 `경품`, `당첨`이 있지만 **ERD에 존재한다고 자동으로 MVP 필수가 되는 것은 아니다.**

| ID | 기능 후보 | 결정할 규칙 | 상태 |
|---|---|---|---|
| FR-26 | 설문별 경품 등록 | 경품 수량, 방식, 확률의 유효성 | 미결정 |
| FR-27 | 당첨 기록 | 제출된 응답만 대상인지, 응답당 1회 당첨인지 | 미결정 |
| FR-28 | 지급 상태 관리 | 지급 대기·완료·실패 등 상태 정의 | 미결정 |
| FR-29 | 자동 추첨 | 즉시 추첨/사후 추첨, 재고 초과·동시성 방지 | 미결정 |

## 3. 공통 데이터 규칙

- **소유권:** 작업공간별 데이터 접근 권한을 서버에서 검증한다.
- **참조 무결성:** 외래키로 부모·자식 관계를 보호한다. 응답의 질문/선택지 소속 일치 여부는 서비스에서도 검증한다.
- **중복 방지:** 필요한 복합 UNIQUE 제약을 명시한다. `답변(응답ID, 질문ID)`와 `멤버십(회원ID, 작업공간ID)`를 우선 검토한다.
- **시간:** 저장·표시 시간대 정책을 통일한다.
- **개인정보:** 참여 식별 토큰, 전화번호 등 보관 기간과 삭제 정책을 결정한다.
- **삭제:** 응답이 있는 설문·질문·선택지의 물리 삭제는 데이터 정합성 관점에서 제한을 검토한다.

## 4. 개발 전 결정할 항목

- [ ] **P0** 발행 후 질문의 수정 허용 범위(질문 내용/유형/필수 여부/삭제)
- [ ] **P0** 중복 참여 판단 단위(설문 기준), 식별 토큰 및 재참여 정책
- [ ] **P0** 비회원 응답 임시저장 재개 방법과 만료 정책
- [ ] **P0** 멤버십 권한 범위 및 작업공간 소유자 정책
- [ ] **P0** 응답 제출의 멱등성·동시성 처리 방식
- [ ] **P1** 경품·당첨을 MVP에 포함할지, 포함한다면 최소 범위
- [ ] **P1** 요약 엔티티 사용 및 갱신 방식
- [ ] **P1** 소셜 로그인 도입 시점

## 5. 완료 기준 (MVP)

- [ ] 회원이 작업공간·캠페인·설문을 만들고 발행할 수 있다.
- [ ] 설문에 단답·장문·단일·복수 선택 질문을 추가할 수 있다.
- [ ] 각 설문에 여러 링크를 생성하고 QR로 공유할 수 있다.
- [ ] 비회원이 설문에 응답하고 제출할 수 있다.
- [ ] 필수값·기간·상태·소속 관계를 서버가 검증한다.
- [ ] 중복 제출 정책과 중복 요청 처리가 구현되어 있다.
- [ ] 질문별 결과 및 링크별 제출 수를 대시보드에서 확인할 수 있다.
- [ ] 작업공간 간 데이터 접근이 차단된다.

---

> 이 문서는 MVP 개발 중 계속 수정하는 **단일 요구사항 원본**이다. 미결정 사항은 확정 시 상태를 변경하고, 관련 DB·API·테스트도 함께 갱신한다.
